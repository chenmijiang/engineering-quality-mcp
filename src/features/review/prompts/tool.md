Review code changes in a local Git repository with Pi. Targets: the workspace by default (HEAD to the working tree, including staged, unstaged, and untracked non-ignored files); one commit against its first parent (commit); or a branch range from the merge base of from and to, up to to (from, optional to defaulting to HEAD). The server pins refs to commits and captures the diff; Pi reads the pinned revisions and returns a Markdown report with located findings (severity, trigger, impact, evidence, recommendation) and review limits. Excluded, binary, oversized, symlink, and submodule files are listed as not reviewed. Read-only. Returns completed without a session when there is nothing to review. Like ask_pi, may return needs_input (answer via reply_pi); on completed, ask follow-ups with ask_pi and the same session_id. The diff stays fixed for that session; review again after changing code.
